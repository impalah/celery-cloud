Configuration

The runner is configured with environment variables. On Lambda they are set on the function; locally you can use an .env file (loaded with python-dotenv). All values are read once, when the module is imported.

Integers and booleans are validated at start-up: an invalid value (for example DEBUG_MODE=maybe or CB_FAIL_MAX=five) makes the runner fail immediately with a clear message instead of misbehaving later.

Task definition (TASKS)

TASKS is a JSON dictionary. The key is the name of the task as sent by Celery, and the value is a URL that says where it runs:

URL

Meaning

task://<module>/<function>

Call <function> of the Python module <module>, which must be importable inside the runner image. The module can be a dotted path (task://my_pkg.domain.restar/restar).

lambda://<function-arn>

Invoke the Lambda function with that ARN (an alias or version suffix is accepted).

 
{
  "tasks.add": "task://my_tasks/add",
  "tasks.multiply": "lambda://arn:aws:lambda:eu-central-1:123456789012:function:multiply"
}

Whatever the route, a task has at most 15 minutes to finish (the AWS Lambda limit; see Execution time limit).

An invalid TASKS (not JSON, not an object, or a value without scheme://) stops the runner at start-up. A task whose name is not listed is stored as FAILURE and never runs: TASKS is an allowlist.

Setting TASKS on a function

The value is JSON inside JSON, so avoid shell quoting by using a file:

{
  "Variables": {
    "TASKS": "{\"tasks.add\": \"task://my_tasks/add\"}",
    "CELERY_BACKEND_TABLE": "lambda-runner-tasks",
    "CELERY_BACKEND_REGION": "eu-central-1"
  }
}

aws lambda update-function-configuration \
  --function-name celery-cloud-runner \
  --environment file://env.json

Client configuration

The Celery client is configured with Celery’s own settings; the ones that matter for Celery Cloud are:

Setting

Value

broker_url

sqs://

broker_transport_options["predefined_queues"]

{QUEUE_NAME: {"url": QUEUE_URL}}. The queue must already exist: the client does not create it.

broker_transport_options["region"]

Region of the queue

result_backend

dynamodb://@<region>/<table>. Append ?ttl_seconds=N if you want the client to configure table TTL too (see Result expiration).

task_default_queue

Name of the queue

@app.task(name=...)

Always set it explicitly: it must equal the key used in TASKS.

task_serializer, result_serializer, accept_content

json (default), msgpack or yaml. pickle is rejected (the task is stored as FAILURE: “Unsupported content type”). The runner must use the same RESULT_SERIALIZER.

task_compression

gzip, bzip2 or lzma. Result compression is not supported.
